## v0.36.18.606 — hold + scrub Loop/Ring candidate browser

- .605 additive modeless selection remains the base behavior.
- .606 replaces repeated long-press cycling with an in-gesture candidate browser:
  - long-press an Edge to enter modeless candidate browsing
  - first valid candidate is shown immediately
  - keep Pencil down and drag horizontally to step through candidates
  - release commits the currently visible candidate
- Candidate order:
  1. strict single-seed Loop result, if valid
  2. directed Loop results generated by pairing the held seed with each neighbouring hint edge and invoking the existing two-edge Loop resolver
  3. Ring result(s) from the existing Ring selector
- Results are deduplicated before browsing.
- No topology branch is guessed:
  - ambiguous Loop possibilities become explicit candidates
  - the user chooses by scrubbing
- Existing additive-session rule is preserved:
  - accumulated base selection remains intact
  - only the held seed's contribution is previewed/replaced
- If no Loop is available but a Ring is valid, Ring becomes the first candidate automatically.
- If no Loop or Ring candidate exists, existing selection is left untouched.
- Horizontal scrub step is 32 px per candidate.
- Selection HUD reports Loop/ Ring candidate number and instructs hold + drag + release.
- Touch/finger is still excluded from Edge-hold gestures.
- Existing strict Loop, directed two-edge Loop, and Ring selectors remain the topology authorities.
- .602 gizmo catches and .601 Files-based Nomad handoff remain unchanged.
- HTML shell, main.js pin and version.json are synced to 0.36.18.606.
- Protected src/multi-object-transform.js?v=0.36.1.0 unchanged.
